# Nassila v1.10.1 — Packaged network parity

**Codename:** Packaged network parity  
**Shipped:** 2026-08-23  
**Installer:** Windows x64 NSIS — `Nassila Setup 1.10.1.exe`

### Fixed

- **"Keep my title — find correct DOI" works in installed builds** — the DOI↔title repair searched Crossref / PubMed / OpenAlex from the sandboxed renderer, which the production security policy blocks; every lookup failed silently, so the button appeared dead (dev runs were unaffected). The registry search now runs in the main process via the same lookup pipeline Raqim Resolve uses, with identical semantics: your title is the trusted anchor, the replacement DOI must genuinely belong to it, and only empty fields are filled from the new record.
- **DOI lookup works in installed builds** — the row-level "Find DOI" action and the "Find Missing DOIs" menu used the same blocked path; online enhancement now runs in main.
- **Autocorrect's online step works in installed builds** — same migration.
- **Input-bar "Resolve" works in installed builds** — pasting DOI / ISBN / PMID / URL identifiers and pressing Resolve now resolves through main process.
- **"Update list" (predatory-journal banner) reports failure** with a toast instead of failing silently.

### Changed

- **Network boundary guard** — a new architecture test fails CI if renderer code ever imports network-bound engine modules outside the guarded IPC-fallback sites, so this class of bug cannot silently return.

### Notes

- Root cause of all four fixes: the production Content-Security-Policy (`connect-src 'self'`) forbids renderer network access by design; the affected paths predated the policy and were only ever exercised in dev mode.
