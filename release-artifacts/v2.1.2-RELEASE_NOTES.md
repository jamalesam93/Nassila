# Nassila v2.1.2 — Arabic localization & security hardening

**Codename:** Arabic localization & security hardening · تدقيق التعريب والتحصين الأمني  
**Shipped:** 2026-10-27  
**Installer:** cut with `npm run build:win` when publishing (`Nassila Setup 2.1.2.exe`). Not attached in this commit.

### Added

- **Full 6-form CLDR Arabic pluralization:**
  - Added native Arabic plural grammar rules (`zero`, `one`, `two`, `few`, `many`, `other`) for citation counts, detected issue counts, and manuscript verification tallies in `src/renderer/i18n/locales/ar/translation.json`.
  - Added unit test validation in `tests/unit/i18n-key-parity.test.ts` asserting 100% key and plural-form parity between English and Arabic locale catalogs.
- **Zero-dependency ICO rasterization:**
  - `scripts/rasterize-icon.mjs` generates Windows `.ico` binaries using `sharp` and an inline raw Device Independent Bitmap (DIB) stream encoder. Output is bit-for-bit identical to the legacy encoder (361,102 bytes). Removed `to-ico` and eliminated 85 legacy transitive packages (including `jimp`, `request`, and obsolete image decoders).

### Fixed

- **Arabic translation & terminology audit:**
  - Replaced English calques, literal translations, and transliterations across the entire UI with authentic Arabic academic and bibliographical terms.
  - Refined predatory journal terminology to standard scholarly Arabic (`دوريات ومجلات وهمية / افتراسية / احتيالية`).
  - Aligned native application menus (`src/main/menu-i18n.ts`) with Arabic platform conventions and RTL typographical layout.
- **PDF.js worker & resource lifecycle leaks:**
  - PDF document loading tasks are now systematically destroyed in `finally` blocks (`loadingTask.destroy()`) across all 5 extraction and OCR call sites (`src/engine/manuscript/pdf-extract.ts`, `src/engine/papers/match.ts`, `src/main/maktab/indra-ocr.ts`, `src/main/maktab/arabic-paddle-ocr.ts`, `src/main/maktab/tesseract-ocr.ts`) and evaluation scripts (`scripts/probe-ocr-golden.mjs`, `scripts/eval-arabic-ocr.mjs`).
  - Prevents worker memory accumulation and dangling file locks during high-volume manuscript and folder-scan auditing.

### Security

- **Electron upgrade:**
  - Upgraded `electron` from `41.10.2` to `^42.11.16` (`42.11.18`), clearing all 14 active Electron security advisories.
- **PDF.js upgrade:**
  - Upgraded `pdfjs-dist` from `5.4.447` to `^6.2.108` (`6.4.299`), resolving known PDF parser vulnerabilities and adopting the v6 worker destruction API.
- **Dependency audit: 0 vulnerabilities:**
  - Pinned `onnxruntime-node@1.29.0`, upgraded `sharp@^0.35.5`, and updated transitive dependencies (`adm-zip@0.6.1`, `@xmldom/xmldom@0.8.15`, `postcss@8.5.32`, `vite@6.4.5`, `vitest@4.1.12`).
  - Production and full dependency audits report zero vulnerabilities (`npm audit --omit=dev` and `npm audit`).

### Changed

- **CI build optimization:**
  - Added `ONNXRUNTIME_NODE_INSTALL: skip` to `.github/workflows/ci.yml` to prevent redundant Linux GPU package downloads during test and packaging runs.
- **Node runtime engines:**
  - Updated `engines.node` specification in `package.json` to `>=22.13.0 || >=24`.

### Unchanged

- **Arabic L3 grounding stays unvalidated.** 2.2.0 Sanad Arabic remains paused for budget. Sanad on the Hugging Face Hub remains **9B FT-6** (v119).
- **Arabic OCR dual-track architecture:** In-app Indra runs on onnxruntime-node when downloaded (~14 MB); packaged Paddle PP-OCRv5 acts as the offline fallback.
